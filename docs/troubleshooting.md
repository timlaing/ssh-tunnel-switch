# Troubleshooting

Start with `tunnel-switch validate --config /path/to/config.yaml`, then check SSH and proxy connectivity. Use the same account and SSH configuration as the running service.

| Symptom                              | Check                                                                                                                                                                                                                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Configuration missing                | Pass `--config`; version 1.0.0 also checks `~/.config/ssh-tunnel-switch/config.yaml`, then `./config.yaml`. Use `init-config` to create an example.                                                                                                                        |
| Validation fails                     | Unknown fields, duplicate server names, invalid sockets and missing identity files are rejected. Relative identity paths resolve from the YAML directory.                                                                                                                  |
| Config edit has no effect            | Check `config_reload` in `/status`: `last_error` shows a YAML that failed to validate (the running configuration is kept) and `deferred` names socket changes awaiting a rebind. Listen addresses need a restart; a `proxy` change is adopted by the next rotation.        |
| Reload returns 429                   | A rotation is in progress; trigger the reload again once it has finished. A reload never interrupts a rotation.                                                                                                                                                            |
| SSH fails                            | Verify `ssh -G <alias>`, known-host fingerprints, key/agent access and server TCP-forwarding permissions. Batch mode does not prompt.                                                                                                                                      |
| Service differs from a terminal      | The systemd account has its own SSH home and does not inherit the desktop SSH agent. See the deployment guide.                                                                                                                                                             |
| Socket already occupied              | Run one service per SOCKS socket. Stop the owning service normally or choose another socket; this service never kills unrelated processes.                                                                                                                                 |
| REST returns 401                     | The token must match `api.token`. A reload (file watch, `POST /reload`, SIGHUP or `systemctl reload`) applies a changed token immediately; update clients with the new token.                                                                                              |
| Rotation returns 429                 | Respect `Retry-After`. Rotation requests are not queued; avoid automatically issuing a second switch when another caller may already be rotating.                                                                                                                          |
| Rotation returns 503                 | The rotation already tried every server and none connected; `last_error` shows the last failure and the log names each attempt. Check SSH authentication, forwarding and readiness. After the cooldown, the next rotation starts the list again from the following server. |
| Need rotation history                | Timestamped lines are written to `logging.file`, naming each server an attempt targeted and why it failed, which were skipped for the next server, and every attempt when all of them failed. Raise `logging.level` to `DEBUG` for more detail.                            |
| Proxy returns 502                    | The SOCKS tunnel or destination is unavailable; there is no direct fallback. Check `/status` and SSH logs.                                                                                                                                                                 |
| Proxy returns 503                    | The HTTP proxy connection limit was reached. Check active clients and `max_connections`.                                                                                                                                                                                   |
| Stream closes despite active traffic | Upgrade to 1.0.0 or later, which measures CONNECT inactivity across both directions. Existing connections close during rotation.                                                                                                                                           |
| Restart selects an unexpected server | Check `state_file`, `server_name` and CLI overrides. Version 1.0.0 remembers the last successful server. Invalid state fails startup; state whose server was removed or renamed falls back to the first configured server.                                                 |
| Cannot save token or state           | Check parent-directory permissions and systemd writable paths. Saving uses atomic replacement and needs directory access.                                                                                                                                                  |
| Log writes refused                   | The log path must be a regular file, the log directory must not be group-writable or world-writable (sticky `/tmp` is exempt), and the log file is opened without following symlinks. Warnings and errors still reach stderr.                                              |
| Missing `init-config` command        | Version 0.1.0 predates it. Use the example YAML or upgrade to 1.0.0.                                                                                                                                                                                                       |

Use direct REST calls when diagnosing routing: `curl --noproxy '*' -H 'Authorization: Bearer <token>' http://127.0.0.1:8765/status`. Do not share the real token, private keys, hostnames or unredacted journal output.

The service does not automatically restart an exited SSH subprocess while the API remains running. Diagnose the failure and request rotation after the cooldown. Systemd can restart a failed Python process; that is a different lifecycle.
