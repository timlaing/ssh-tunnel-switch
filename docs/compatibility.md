# Compatibility

| Component            | Requirement or verification                                                                                                                                                       |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Python               | 3.12+; CI tests 3.12, 3.13 and 3.14 on Linux and 3.13 on macOS.                                                                                                                   |
| OpenSSH              | A system `ssh` client with dynamic SOCKS forwarding, known hosts and noninteractive key/agent authentication.                                                                     |
| Real SSH integration | Linux CI uses disposable Docker OpenSSH servers to test forwarding, rotation, strict host-key rejection, server loss, recovery and cleanup. No personal SSH credentials are used. |
| HTTP proxy           | HTTP/1.1 absolute-URL forwarding and HTTPS CONNECT. HTTP Upgrade is unsupported; CONNECT carries destination TLS unchanged.                                                       |
| Service deployment   | Linux systemd example included. Foreground operation is tested on macOS; no launchd unit is supplied. Windows is not tested.                                                      |
| Python distributions | Wheel and sdist install in fresh environments. Examples and license are checked; the wheel ships the `init-config` template.                                                      |
| External clients     | Any supported HTTP/SOCKS proxy client or bearer-authenticated REST client. No plugin dependency.                                                                                  |

Version 0.1.0 requires explicit YAML configuration and starts with the first SSH server. Version 1.0.0 adds configuration discovery, persistent restart selection, startup overrides, `init-config`, and the CONNECT stream inactivity fix. Version 1.1.0 adds timestamped file logging through the `logging` YAML section and the interactive status display shown by `serve` on a terminal. Version 1.1.1 shows the SSH server name beside the connection ID in that status panel and makes the panel's connection fields a single consistent snapshot. Version 1.2.0 lets one rotation fall through the server list when a server refuses SSH, so `POST /rotate` reaches a working server in a single call. Version 1.3.0 applies configuration changes without a restart (file watcher, `POST /reload`, `SIGHUP`), deferring a changed SOCKS bind to the next connection change and a changed API or HTTP proxy listener to a restart, adds status-panel control keys, and reports the running version in `tunnel-switch --version` and the `GET /status` `version` field. Version 1.4.0 lets the panel's rotate key bypass the rotation cooldown, adds the Alt+S server picker, and adds a request counter: the panel's `HTTP requests` row and the `GET /status` `requests` totals show how many requests the HTTP proxy carried over the current SSH connection and over the one before it. Version 1.4.1 opens that picker with Ctrl+S as well as Alt+S, for terminals whose Option key types a character instead of an Escape sequence, and switches software flow control off while the panel is up so the key reaches it, reporting in the log when a terminal refuses the change. Version 1.4.2 draws that picker as a pop-up over the dashboard instead of a list beneath it: it is sized to the display and scrolls inside itself when the configured servers do not fit, counts what it hides in its title, and keeps the highlighted server selectable even on a display too short to spare any rows. The `tunnel-switch` CLI, `tunnel_switch` imports and REST endpoint shapes are retained.

Local tests use fixtures and do not establish that a particular remote SSH account or client application is correctly configured. See the current [CI runs](https://github.com/timlaing/ssh-tunnel-switch/actions/workflows/ci.yml) and release notes for evidence tied to a revision.
